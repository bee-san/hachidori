# Decisions, superseded ideas, open questions, risks, alternatives

Sources are the original issue body (kept verbatim in [history/original-body.md](history/original-body.md)) and the 29 comments on [#334](https://github.com/bee-san/hachidori/issues/334), indexed in [history/comments.md](history/comments.md). Later comments by bee-san override earlier ones. Where two sources disagreed, the table below records the resolution and the reason for it. bee-san rewrote the issue body into an MVP brief at 18:23 UTC (D29–D31), and the owner's direct update of 2026-09-28 (D20, D27, D28) came after that. The latest comment, [c28](https://github.com/bee-san/hachidori/issues/334#issuecomment-5872606542) (2026-09-28 15:00 UTC), overrides everything before it. It says that themes are their own popup, never CSS or JS over the normal one; that they are reviewed by bee-san, so the security machinery goes; that Nazeka is text only; and that every theme is benchmarked.

## Risks

- **Refactor risk in two 4,000-line files.** Mitigations: behaviour-preserving seams first (T-10/T-11/T-14 legacy adapter), a lock per hotspot, screenshots and serialised-DOM equality tests, benchmark before and after each seam PR.
- **Policy drift.** Bundling is the conservative reading of the MV3 remote-code rules. If Google narrows even bundled extensibility, renderer themes fall back to Default through `rendererThemes: false`.
- **Renderer JS has content-script privileges.** Accepted by bee-san (c28): every renderer is his reviewed PR, and vendoring is a second reviewed diff. What remains is robustness: the failure fallback and the contract lint.
- **Public API surface.** The model, actions, components, roles and shared component classes become a contract, so it is versioned (renderer-api.md §11) and the contract runner in themes CI runs against the pinned Hachidori commit.
- **Release coupling.** Renderer fixes wait for a Hachidori release (a one-line vendor bump). Palettes and variants still update through the Store's Refresh.
- **Cold-start cost** with `all_frames: true`: T-05 measures it and T-20 enforces parity with the benchmark gate.
- **Overlay hosts** (GSM vendors the whole extension, docs/overlay-mode.md:17-28) may lack `chrome.scripting`, so the `rendererThemes` capability falls back to Default.
- **Community renderer quality** (10 proposals, 30-64 KB each): same gates as first-party renderers; bee-san approves inclusion.
- **CI fonts vs users' fonts** in screenshot comparison: fonts-noto-cjk plus a 2 % tolerance.

## Alternatives considered

- **Keep everything in `reader.css`.** Every theme needs a release, and a layout needs JS anyway.
- **CSS-only themes** (this issue's first version): cannot remove the top bar or restructure entries, and still pay for Default's rendering (c28).
- **Post-render transformation of Default** (the prototype): works (0.3 ms p95) but builds Default first and scrapes its DOM, which pays Default's rendering cost. Superseded by c26 and c28.
- **A few hard-coded layout presets** (Yomitan-style `data-*` modes such as `glossaryLayoutMode`/`resultOutputMode`): c26 says renderers are "not limited to choosing from a few hard-coded layout presets". Default may still adopt such modes for its own options.
- **Runtime-installed JS** (fetch + eval/import, a JSON "script" interpreter, `userScripts` registration from the Store, a sandboxed `'unsafe-eval'` page): each is either a listed MV3 violation or unusable ([security.md](security.md#javascript-delivery-paths)). c28's review does not change a store policy. `userScripts` stays for the user's own Custom JavaScript.
- **Renderer in an extension iframe** (Yomitan's popup model): stronger isolation, but a second document per popup level, message-passing for every action, and a rewrite of positioning. Hachidori's single shadow root is kept.
- **Stylus-style "Install from URL"**: a new privacy endpoint per URL and no review by bee-san (open question 5, moot after c28).
- **Vendor a YAML parser**: about 40 KB for no gain over CI-generated JSON.
- **Benchmark only JS themes**: a CSS theme can force layout too (`:has()`, filters, large shadows, `backdrop-filter`: Tango measured +11 ms first / +31 ms complete from DOM plus blur with a 0.2 ms hook).
- **One long-lived draft branch** (c11): rejected. It would conflict constantly, and the owner confirmed flag-on-main (D20).
